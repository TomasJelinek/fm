# Inline Tree Move Implementation Plan

> Use `superpowers:subagent-driven-development`; backend and frontend ownership
> are separate, with one Windows Cargo build lease.

**Goal:** F6 moves selected native tree occurrences through the existing verified
Move queue and progressively clears only successfully completed roots.

**Architecture:** Generalize exact tree capture to an immutable transfer intent,
prepare native Move authorities on the backend, and share the ordinary Move
worker and existing occurrence-completion selection path.

**Tech stack:** Existing Rust/Tokio/Slint services; no new third-party dependency
or public plugin ABI changes. Native UI integration tests use the existing internal
platform crate as a dev-dependency.

**Spec:** [Tree Move](../specs/2026-11-10-tree-move-design.md).

## Global constraints

Preserve unrelated dirty work, raw Unicode/provider identities, backend-only I/O,
platform separation, rustfmt 100 columns, source files at most 100000 bytes.
Generated evidence belongs under `_build/qa/tree-move`; reuse existing targets.
Do not change ordinary per-file verified Move semantics or weaken source-removal
proofs. No commits or deployment until integrated review/verification. Do not mark
the overall application goal complete for this integration.

## Review focus

- Bound Move intent cannot be upgraded from a Copy-only capture.
- Mixed virtual/native input fails before native source or destination preparation.
- Retry retains the original native Move identity and removal authority.
- Descendant captures and stage-cleanup tickets retain leases after source close.
- Root completion requires verified removal; later selection/navigation is safe.
