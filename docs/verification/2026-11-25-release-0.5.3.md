# Release 0.5.3 and its acceptance runs

Recorded on 25 November 2026. The [0.5.3 preview](../releases/0.5.3.md) was built,
tested and published from `c7ef1e5c` (tag `v0.5.3`); `d1fe2fa3`, an acceptance scenario
change made after the release runs, is not part of it.

## Builds and packages

- Windows: the release build of `c7ef1e5c` in a clean detached checkout, Windows 11 x64;
  the release ZIP `midnight-explorer-0.5.3-x86_64-pc-windows-msvc.zip`
  (259,032,563 bytes, SHA-256 `8dbc23e083aad31aef445e2ea3c5ceccce4ff4e80aeaeb4c19b8073ed39da20f`).
  Its FFmpeg 9.0.2 libraries were built for this release with `scripts/build-media-ffmpeg.sh`
  (`msvc`) from the official archive with the pinned SHA-256.
- Linux: the release build and package of `c7ef1e5c` in a WSL 2 Ubuntu 24.04 clone,
  `midnight-explorer-0.5.3-x86_64-unknown-linux-gnu.tar.gz` (435,542,438 bytes, SHA-256
  `3f6de6517aa2b238f0fd9a114bd721963e2346944b5b270dba2502e52ecf10e6`).
- Both archives carry `LICENSE.txt` (Windows) or `LICENSE` (Linux) and a `README.txt`
  that begins "Midnight Explorer 0.5.3"; each `BUILD-INFO.json` names `c7ef1e5c`.
- Before publishing, the unpacked archives' `midnight-explorer` and
  `midnight-elevated-listing` executables were byte-identical to the tested release
  builds on both systems; the ZIP held no PDB, ILK or object files; its `thumbnailers`
  files named no grant for the workers' AppContainer (as any ZIP extraction leaves them);
  and the ignored extracted-installation tests (`midnight-thumbnail-host` integration
  `extracted_installation`, `midnight-media-host` `extracted_installation`) started the
  video thumbnail helper and both playback helpers from a copy of that folder in a
  private profile installation: both PASS.
- `SHA256SUMS` was signed by the owner with the release key; `release-signing.py
  verify --version 0.5.3` accepted it, and the four assets downloaded back from the
  published release matched `SHA256SUMS`, verified again, and the downloaded
  `SHA256SUMS.minisig` was byte-identical to the signed one.

## CI

Hosted CI passed every job at `c7ef1e5c` (the release) and `d1fe2fa3`. The run at
`d1fe2fa3` had no warning or error annotations; the run at `c7ef1e5c` had one warning
from GitHub's runner (an action download answered HTTP 500 and the retry succeeded).
The run at `3a46c0f2` failed `folder_sizes::refresh_honors_target_continuation_until_the_ui_retires_its_completion`
on Linux: an entry-size scan announced its completion before marking itself finished,
so a refresh handled in between still continued its sizes. `c7d7bcb3` marks the scan
finished first; the folder-size integration tests then passed 30 runs on Linux and
10 on Windows.

After the release, the runs at `e21ff7a7`, `c120eaab`, `ced5a009` and `a5e5b1a4` also passed
every job, with no warning or error annotations.

## Whole-suite acceptance at c7ef1e5c

Full-scale fixture, seed `0x4d45414343455054`, debug test builds with the release
packages of `c7ef1e5c`.

| System | Run | Passed | Warned | Skipped | Failed | Time |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Windows 11 | `20261125-002632` | 112 | 1 | 3 | 1 | 3,811 s |
| Linux (WSL 2, Ubuntu 24.04, ext4) | `20261124-235915` | 113 | 1 | 2 | 1 | 3,199 s |

The warnings are `viewers_files`' AppArmor case (no AppArmor on Windows or in WSL); the
skips are gated volumes and tools the machines do not have. Neither failure was a
product defect of `c7ef1e5c`:

- **Windows, not reproduced:** `viewers_combinations` › small viewer windows waited 60 s
  for the HTML viewer's page (`viewers_files` showed HTML pages in the same run); the
  rerun at the same commit passed.
- **Linux, scenario timing:** `viewers_compare` › three differences took the first
  difference's position while the glide was still moving (the changed line shows before
  the content comes to rest, since the glide starts at its full speed), so the wait for
  P to return to it timed out although the comparator showed row 11, the first
  difference. `d1fe2fa3` takes each position once the content holds still.
