# X11 drag/drop cleanup ordering

Release preflight reproduced the CI failure in
`x11_registers_verified_proxy_and_restores_previous_host_properties`: immediately
after dropping a session, a separate connection could still read its old
`XdndProxy` property (WINDOW atom 33 instead of NONE). A repeated run of the
existing optimized test reproduced the same assertion locally.

`flush()` sends buffered requests but does not wait for server processing.
Session teardown now uses x11rb's `sync()` processing barrier after restoring
host properties and destroying the proxy. Errors during disconnection remain
nonpanicking. This work stays on the backend actor; teardown already reads a
property synchronously, so no I/O moves onto the UI thread.

The regression reads the host properties through a separate connection immediately
after teardown, without sleeps, over 32 session lifetimes. An optimized native
test build using the existing release dependency artifacts passed all 12 drag/drop
tests, including all 10 isolated X11 tests. The independent review found no
actionable issue. Full Cargo release validation is also required for publication.

The separately reported footer issue stopped reproducing before any footer code
change. Native release window captures showed the complete footer at startup,
after resize/maximize/restore, with both GPU and software rendering. No speculative
footer patch was included or claimed as a fix.
