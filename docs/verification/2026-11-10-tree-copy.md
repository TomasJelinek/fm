# Copy from inline directory trees — 10 November 2026

Windows debug and Windows/Linux backend/software-window qualification completed.
This report concerns the captured F5 workflow; the wider inline-tree/provider
migration remains partial.

## Scope

F5 uses selected native/archive tree occurrences, including nested directories,
or the focused ordinary occurrence when no marks exist. Capture precedes the
ordinary destination dialog and survives navigation once that draft opens.
Confirmation enters the existing verified copy queue. Root completion removes
only the corresponding successful marks through ordered selection processing.
F6 and destructive/clipboard actions retain their separate tree guards.

The implementation follows Salamander's captured selection/caret fallback and
explicit parent-row exclusion (`src/fileswn8.cpp::FilesAction`, lines 170–184,
357–373), archive extraction (`fileswn7.cpp::UnpackZIPArchive`) and provider
capability routing (`fileswna.cpp`). No implementation code or assets were copied.
The user's progressive successful-root deselection requirement is retained;
selection is not cleared merely because an operation script was accepted.

## Defects found during implementation

- F5 after a rejected selection edit originally waited for a revision that
  could never be acknowledged. It now uses the last accepted revision when no
  local selection intent remains. The failing UI run is retained in
  `_build/qa/tree-copy/ui-selection-red.log`.
- Archive traversal formerly keyed visited directories by a member number alone.
  Equal member numbers from distinct mounts must remain distinct; the worker
  now uses the complete virtual identity. The behavioral failure is retained in
  `backend-behavior-red.log`.
- Rejected/unstarted captured requests could release final provider ownership
  on the async dispatcher. Explicit worker retirement and abort ownership guards
  cover admission refusal, cancellation, missing services and shutdown.
  `backend-retirement-red.log` records the wrong-thread destructor failure.
- Moving shutdown disposal to a worker initially delayed closure of queue
  receivers. Receivers now close synchronously before payload disposal.
- An additional failed-send case released queue capacity before the captured
  source destructor finished. `backend-retirement-order-red.log` records that
  ordering failure; the rejected raw payload, receipt and capacity must retire
  in one awaited worker operation.

The first native Engine/Slint bridge fixture displayed the same folder in both
panes. Copy succeeded (two files, 1,012 copied and verified bytes), but the normal
destination refresh also retired the source tree. The assertion waited on the
harness's retired selection snapshot. The copy fixture now uses distinct folders
so it tests successful-root deselection while the source tree remains adopted.
`ui-native-diagnostic.log` records the diagnosis. No production refresh behavior
was changed to accommodate the test.
