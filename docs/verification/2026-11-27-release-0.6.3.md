# Release 0.6.3 and its acceptance runs

Recorded on 27 November 2026. The [0.6.3 preview](../releases/0.6.3.md) was published
from `7ce68224` (tag `v0.6.3`, on the `release-0.6.3` branch): the Windows installer
installs again and updates itself, Dark is the default dark theme, a folder opened with
authorization stays open, Delete or F8 where no Trash takes the items asks for a
permanent delete at once, copies to FAT32, exFAT and network shares without usable file
IDs on Windows, faster JPEG opening, and the watch, viewer-exit and copy-shutdown fixes
the notes list.

`7ce68224` is `0423b7d1` plus one commit that changes only documents and the MSI
installation test; `0423b7d1` differs from `bc162919`, the built commit, in documents and
scripts only. The binaries are therefore those of `bc162919`, and the packages record
`7ce68224`. Main went on to `220972f8` with the same change and an HTML viewer fix
(`e3a03d51`) that is not in 0.6.3.

## CI

Hosted CI passed every job at `7ce68224` (run 46033318134, started by hand on the
`release-0.6.3` branch), including the Windows release job's MSI installation test:
install, upgrade from 0.0.1, refused downgrade, smoke tests, repair and removal in each
scope, the all-users folder's permissions, and the published 0.6.1 and 0.6.2 MSIs
upgraded in place. The runs on main before it each failed in a way that a following

all-users shortcut, the Installed apps icon and a Linux-only path test (`fbbe0eab`),
the same version expected in both scopes (`c236a689`), an HTML viewer watchdog
wake-up race (`bc162919`, fixed on main by `e3a03d51` after this release) and the
copies in both scopes (`0423b7d1`).

at a time, on the binaries of `bc162919`.

| System | Commit | Run | Passed | Warned | Skipped | Failed | Time |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| Windows 11 | `0423b7d1` | `20261127-153450` | 113 | 2 | 3 | 1 | 1,318 s |
| Linux (WSL 2, Ubuntu 24.04, ext4) | `bc162919` | `20261127-150635` | 116 | 1 | 2 | 0 | 940 s |

The Windows failure was `viewers_scroll`: the PDF viewer refused to open because its
staged plugin manifest (`image-viewer.json`) had "changed since capture". Its length and
write time were unchanged; only its change time had moved, 55 s after the capture.
Something on the machine touched the file's metadata, as it had touched fixtures of two
unit tests before ([test-speed pass](2026-11-25-test-speed-pass.md),
[PDF scrolling](2026-11-21-pdf-scrolling.md)). Run alone right after, the scenario
passed in 446.6 s (run `20261127-155738`). Whether a change-time-only change of a plugin
manifest should be revalidated by content instead of refused is open.

The warnings are review flags in screenshots (low-contrast text in one theme's sample,
`viewers_selection`) and `viewers_files`' AppArmor case; the skips are the full UI
matrix, gated volumes the machines do not have, and on Windows `files_trash` and
`journeys_links_readonly`.

## MSI installation test

CI's release job installed the MSI on a disposable Windows runner for the first time in
this release. Its runs found three defects, each fixed before `7ce68224`:

- The all-users Start menu shortcut started in the installing administrator's profile:
  Windows Installer expands a profile variable when it creates the shortcut. It now
  starts in the Windows drive's root.
- The test expected the same version installed in both scopes; Windows Installer
  maintains the installed copy instead.
- With an older copy just for you beside the all-users copy, removing the per-user copy
  left its files, shortcut and key: both copies register the same component codes. The
  package supports one scope at a time; 0.6.3 documents it, and the installer refusing
  the second scope is open (REL-05).
