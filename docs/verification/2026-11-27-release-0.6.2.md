# Release 0.6.2 and its acceptance runs

Recorded on 27 November 2026. The [0.6.2 preview](../releases/0.6.2.md) was built,
tested and published from `029cdfff` (tag `v0.6.2`): drives that follow the system's
notifications, the Trash refusal question in its own window, Find accepting a change of
the change time alone, folder sizes past unreadable entries and sorting by size, Retry
with authorization from the user's own installation, and the dual-scope Windows MSI.

## Builds and packages

- Windows: the release build of `029cdfff` in a clean detached checkout, Windows 11 x64,
  with the FFmpeg 9.0.2 libraries built from the official archive with the pinned
  SHA-256, and the explorer built after the authorization helper so that it records the
  helper's digest. The release ZIP `midnight-explorer-0.6.2-x86_64-pc-windows-msvc.zip`
  (246,280,121 bytes, SHA-256
  `20fbbc322aa6783f2daab924167ca21d158f0d660fc47b33e22f21271e63e17e`).
- Windows installer: `midnight-explorer-0.6.2-x86_64-pc-windows-msvc.msi` (193,744,896
  bytes, SHA-256 `c392e630c5b230f6aa1cb6059d41cab1e22bdcc529be2e32b9d49ce0f695b09b`),
  the dual-scope package built from that ZIP in 374 s; its built-in verification compared
  every packed file with the ZIP and passed. The owner installed it with Just for me over
  the installed 0.6.1 MSI and used Retry with authorization on a folder the account cannot
  read: Windows asked for approval and the folder was listed. The For all users choice,
  repair and removal remain to be exercised (REL-05).
- Linux: the release build and package of `029cdfff` in a WSL 2 Ubuntu 24.04 clone,
  `midnight-explorer-0.6.2-x86_64-unknown-linux-gnu.tar.gz` (207,730,794 bytes, SHA-256
  `9bfa97d0923b92cc09ffff81d00e9def4d79c69e05bcdf98f8929603797888ae`).
- Both archives carry `LICENSE.txt` (Windows) or `LICENSE` (Linux) and a `README.txt`
  that begins "Midnight Explorer 0.6.2"; each `BUILD-INFO.json` names `029cdfff`.
- Before publishing, the ZIP's `midnight-explorer` and `midnight-elevated-listing`
  executables were byte-identical to the tested release build, the ZIP held no PDB, ILK
  or object files, and `package-release.py check-authorization-helper` found the packaged
  explorer's recorded digest equal to the packaged helper's SHA-256 (`c9358ec7…62a9`).
- `SHA256SUMS` lists the three downloads and was signed by the owner with the release
  key; `release-signing.py verify --version 0.6.2` accepted it. The five assets downloaded
  back from the published release matched `SHA256SUMS`, which verified again, and the
  downloaded `SHA256SUMS.minisig` was byte-identical to the signed one.

## CI

Hosted CI passed every job at `029cdfff` (run 45952607510). The runs at `ebe92ba4`,
`d448da09` and `04aa64e4` before it each failed one test that the following commit
corrected: a Linux build-script test still expecting one cargo command, an elevation test
assuming a standard-user owner on the CI runner, and a race in an elastic-pool test.

## Whole-suite acceptance

Full-scale fixture, debug test builds with the release packages, isolated scenarios four
at a time. Linux ran at `ebe92ba4`, whose product code is that of `029cdfff` (only tests
changed after it).

| System | Commit | Run | Passed | Warned | Skipped | Failed | Time |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| Windows 11 | `029cdfff` | `20261127-065417` | 113 | 2 | 3 | 1 | 1,239 s |
| Linux (WSL 2, Ubuntu 24.04, ext4) | `ebe92ba4` | final acceptance of 26 November | 116 | 1 | 2 | 0 | 874 s |

The Windows failure was `tools_checksum_algorithms`, which timed out after 60 s waiting
for the Checksums window to open; run alone right after, it passed in 4.4 s (run
`20261127-071653`). Its cause under load is not yet known. The warnings are review flags
in screenshots and `viewers_files`' AppArmor case; the skips are gated volumes and tools
the machines do not have, and on Windows `files_trash` and `journeys_links_readonly`.
