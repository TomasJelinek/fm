# Panel and dialog polish verification

Scope: the November 8 filter clarification and preceding UI follow-up. The
unrelated in-progress inline-tree implementation is not claimed as available.

## Changes

- Panel Filter uses OK to validate/apply, Cancel to discard the draft, and Show
  all to disable filtering while preserving its last expression. A direct × on
  the panel indicator also disables it. Pending validation cannot restore it.
- View and Sort belong to each panel's drive bar; compact windows retain the
  controls beside the path. Other actions remain on the shared toolbar.
- Archive settings retain built-in checkboxes. Custom extensions are removable
  values with a leading ×; the final + opens an inline editor. Enter adds a
  validated extension to the draft; Options OK saves and Cancel discards it.
- Compare and Jobs share a bounded scrolling footer. Primary actions and the
  dismissal have consistent height. Cancel job distinguishes stopping work from
  closing Jobs. Necessary destructive confirmations remain.
- Fourteen original action icons have restrained accent colors and light/dark
  variants. Native artwork and the approved archive artwork are preserved.

## Review and causal tests

Independent review found that the panel filter × initially omitted the raw
pointer capture context and cancellation flag. The new widget regression failed
when a changed filter received a delayed press (`filter-press-red.log`). The
control now captures the panel, directory and filter label and rejects cancelled
input. The integration regression uses the runtime's actual internal touch
events after raw capture, including navigation, cancellation and the next valid
press. Sending a new public mouse press after cancellation was an incorrect test
sequence: a new press must reset cancellation, as the real input path does.

Screenshot review exposed a seven-pixel vertical mismatch between primary and
dismissal buttons. Stronger geometry assertions reproduced it on both platforms.
Pinning the action row to y=0 avoids centering it within the space reserved for
the horizontal scrollbar. A standalone probe imports the actual footer
component; the full Compare/Filter tests also cover font and density changes.

The first broad Windows run exposed a stale checksum-dialog test that expected
108 closes for nine themes. It now verifies exactly one close for each click
across the current palette list, window sizes, density and pages. There was no
corresponding production checksum-window failure.

Broader tests also needed updates for previously requested behavior: raw command
path insertion without automatic quotes/spaces, Options' loading guard and
OK/Cancel transaction, the shared Hot Paths control's active-pane ownership,
and the clearer Cancel job label. These corrections retain focus, persistence,
shell-binding, no-implicit-execution and viewport assertions.

The custom-command toolbar check found a real initialization issue: initially
visible icons never changed state and therefore never announced visibility to
the backend. A trace contained only false notifications for later offscreen
commands. The repeated button now announces its initial state, retaining the
existing geometry/revision notifications. A standalone probe importing the real
toolbar failed before the fix and passed afterward (`command-icon-probe-red.log`
and `command-icon-probe-green.log`). No I/O runs in this callback; it updates the
existing bounded presentation set for subsequent backend work. Integration tests
cover the compact popup, normal toolbar, initial visibility and scrolling.

No production parent-focus fix was justified: the current implementation passed
the stronger first-frame test, including native event ordering, the painted
cursor edge, offscreen children and progressive listings. See
[parent navigation](../developer/PARENT_NAVIGATION.md). A deployed-release cause
for the user's observed cursor jump has not been established.
