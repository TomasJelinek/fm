# CI repair

The configured remote is `TomasJelinek/fm` on GitHub. Its `build-and-test`
GitHub Actions workflow is the pipeline investigated for the reported failures.

## Observed failures and corrections

- Cargo packaging needs repository ignore files. Partial, sparse SDK checkouts
  omitted blobs that Cargo's libgit2 could not fetch lazily. SDK packaging jobs
  now use a full checkout. Independent plugin jobs still see only their own
  sources and the released public SDK bundle.
- The archive Clippy invocation lost registry configuration when `--config`
  preceded the Cargo subcommand. Passing it to `cargo clippy` fixes resolution
  for the independent Windows and Linux archive jobs.
- The Windows build-hook fixture lacked the new private-deployment script.
  It now verifies app, viewer and deployment ordering and propagates deployment
  failure, alongside application/viewer failure cases.
- `checksums_backend` path-includes the checksum controller module. Its native
  integration tests and the unit test filling all 32 job slots therefore shared
  the same process quota. Serializing only the two worker tests did not isolate
  native consumers: both local full-workspace and CI runs reproduced the failure.
  One test-only fixture now covers every real-quota consumer for the complete
  lifetime of controllers, retained results and individual result rows.
  Production admission, the 32-job limit and 64 MiB budget are unchanged.
- The shutdown test previously sampled an instantly idle shared I/O gate while
  other tests could acquire it. It now proves every permit can be reacquired
  within a bounded deadline after the blocked read exits.
- Three native-platform tests still required empty initial metadata, contrary
  to the existing optional-cache directory-service contract and Windows cached
  enumeration optimization. Shared tests now validate optional values and a
  fresh metadata query after a file changes. A separate Windows test requires
  complete cached metadata to match the native query; production listing is
  unchanged.
- A thumbnail unit fixture required an explicitly exported build directory even
  though Cargo already used the repository's `_build` configuration. It now
  retains both explicit overrides and defaults to the repository's `_build`
  fixture directory, so ordinary workspace tests do not require an extra variable.
- A physical-digit remapping fixture assigned `Ctrl+Digit1` without first
  removing the image viewer's newer default assignment. It now explicitly
  disables that binding before reassigning the chord. Conflict validation and
  actual default shortcuts remain unchanged.
- Run `42414710706` exposed a folder-size fairness assertion that compared final
  callbacks from two independent operation receivers. I/O permits are released
  before those callbacks run, so receiver scheduling can reverse their order.
  The fixture now observes the small folder's completed metadata read while the
  exclusive I/O permit is still held, requires unfinished large-folder work at
  that instant, and validates both final totals. It deliberately delays small
  result delivery until after the large result to cover the observed race.
  The production FIFO gate, scan quantum and storage concurrency are unchanged.

## Evidence

The SDK, archive and viewer corrections passed their actual GitHub Actions jobs.
Run `42410956720` still failed the application checksum tests; it is retained as
the causal CI evidence for the final fixture correction, not a successful run.

Fresh pre-fix `checksums_backend` runs reproduced quota interference on both
platforms. The corrected binary passed with 32 test threads: 19 tests on Windows,
21 on Linux. The quota test still admits exactly 32 jobs, rejects a 33rd while
results are retained, and now additionally verifies that a single retained row
keeps the quota after its parent result is dropped.
Both actual test binaries also passed 100 repetitions at 32 test threads:
1,900 Windows and 2,100 Linux test executions, with zero failures.

Linux build-hook tests passed four checks; the Windows-only deployment check was
appropriately skipped there. Windows build-hook behavior was verified separately
and its actual CI packaging step passed. Logs and stress-run evidence are under
`_build/goal/ci` and `_build/goal/checksum-isolation`.

The complete Windows `--workspace --no-fail-fast` run exposed five failing test
cases across four targets: the listing and service expectations, thumbnail
fixture root, and digit-remapping fixture described above. All other targets
passed. Corrected Windows scopes subsequently passed 15 platform tests (including
the new native cache regression), five thumbnail tests and nine input tests.
Linux listing/service tests passed ten and thumbnail tests four. The original
workspace run's exit 101 is retained; these focused reruns do not rewrite it as
a successful single full-suite invocation.

Windows and Linux strict workspace Clippy and the formatting/source-size checks
passed. The remote pipeline for the pushed checkpoint is still being followed;
local results alone are not reported as a green remote workflow.
