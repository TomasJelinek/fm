# Native inline-tree Move and transfer reconciliation

F6 now shares the typed F5 capture with immutable Copy/Move intent. Native files
and selected nested native directories use the existing verified Move queue;
archive Move is refused. Source files are removed only after independent
destination verification, with postorder empty-directory removal. This does not
introduce a second Move algorithm or source-recovery workflow.

Terminal Copy/Move results request in-session reconciliation of both adopted
native trees. The backend rereads the root and previously loaded native branches,
including collapsed branches, preserving surviving identities, expansion, marks
and options. Current root action snapshots allow F3/Enter for newly added files
without changing the original session admission snapshot. Failed reads retain
known rows. The mutation gate covers each listing and its installation, but not
UI output backpressure.

## Defects found and corrected

- Failed captured-Move preparation formerly dropped the provider lease before
  retained native authorities. A destructor-order regression reproduced this;
  service ownership now drops before captured input. Cleanup tickets keep the
  provider alive without retaining native source handles.
- Real F6 tests initially completed the native move but left nested ghost rows
  or flattened a root panel, discarding its expansion. The same assertions now
  pass through in-session reconciliation; they were not weakened.
- Review found maintenance could overwrite the version of a queued explicit
  expansion for the same branch. Explicit work now precedes that maintenance
  step; redundant probes are retired. The lost-expansion test failed before
  correction and passed afterward.
- Review also found an unrelated full output queue could strand a completed
  listing's mutation permit. Bounded completion-aware sending now installs that
  one completion and releases its permit before waiting to deliver its result,
  preserving original-response ordering. Tests reproduce the old failure and
  cover accepted selection, full output and navigation/reset.
- Strict root-action validation exposed a test fixture that changed a path
  without updating its raw filename. The fixture now uses `Entry::new`; the
  production validation remains intact.

## Boundaries

These are backend and software-window interaction checks, not GPU/gesture or
complete installed desktop qualification. General watch-driven root refresh,
expanded-branch watches, nested-container discovery and the remaining typed tree
actions are separate work. A live listing is not an atomic filesystem snapshot.
Archive Move, release qualification and macOS are not enabled by this slice.
No third-party dependency or public plugin ABI changed; native UI tests add only
the existing internal platform crate as a development dependency.

The optional Chromium provider is unchanged. Its Windows native HTML rendering,
Find, zoom, resize and Escape evidence remains in the
[HTML viewer report](2026-11-10-html-viewer.md).
