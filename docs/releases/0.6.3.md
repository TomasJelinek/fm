# Midnight Explorer 0.6.3 — preview

A fix release after the [0.6.2 preview](https://github.com/TomasJelinek/fm/releases/tag/v0.6.2):
the Windows installer installs again and now updates itself, and keys pressed while a
folder changes are no longer ignored.

## Downloads

- **Windows x64, installer:** `midnight-explorer-0.6.3-x86_64-pc-windows-msvc.msi`.
  It asks who it is for: **Just for me** installs without administrator rights into
  `%LOCALAPPDATA%\Programs\Midnight Explorer (MSI)` and upgrades an installed 0.6.1 MSI;
  **For all users** asks for administrator approval and installs into
  `C:\Program Files\Midnight Explorer (MSI)`. Each adds a Start menu entry and an entry
  under Settings › Apps › Installed apps to repair or remove it; removing it leaves your
  settings. The installer is unsigned.
- **Windows x64, archive:** `midnight-explorer-0.6.3-x86_64-pc-windows-msvc.zip`. Extract
  the complete archive to a folder and run `midnight-explorer.exe`; keep the `viewers`,
  `filesystems` and `thumbnailers` folders beside it. Targets Windows 10 22H2 and
  Windows 11; the executable is unsigned. Both Windows downloads need the Microsoft
  Visual C++ x64 runtime if it is not already installed.
- **Linux x86-64:** `midnight-explorer-0.6.3-x86_64-unknown-linux-gnu.tar.gz`. Extract it
  with tar and run `./midnight-explorer` in an X11 or Wayland desktop. Built on Ubuntu
  24.04 (glibc 2.39 baseline); the archive's README lists the runtime packages.
- **`SHA256SUMS`** and **`SHA256SUMS.minisig`:** the checksums of the three downloads and
  their minisign signature by the release key. 0.5.1 to 0.6.2 offer this version through
  their update check and install it only when the signature and checksums match.

## Upgrading

- **From an extracted 0.6.2 or earlier:** use the update button beside Options and
  About, or About › Check for updates; or extract the new archive over a copy of the old
  folder.
- **From a 0.6.1 MSI installation:** run the 0.6.3 MSI once and choose **Just for me**;
  it replaces 0.6.1 in place. (0.6.2's MSI could not install; see Fixes.)
- **From 0.6.3 on**, an MSI installation updates itself: the update dialog downloads the
  next release's MSI, checks it against the signed `SHA256SUMS`, closes the application,
  lets Windows Installer install it (with Windows' administrator prompt for an all-users
  installation) and starts the new version again.
- Settings are kept as they are.

## New and changed

- **MSI installations update themselves.** The update dialog offers **Install now** for
  a copy installed with the MSI, just for you or for all users, as it does for an
  extracted copy. The new version opens afterwards with a note that it was updated; if
  Windows Installer is cancelled, busy with another installation or needs a restart, the
  next start says so and nothing is half installed.

- **Dark is the default dark theme.** A new installation, and settings that kept the
  default dark palette, use Dark instead of Blue on a dark desktop. Another dark palette
  you chose stays; Blue was saved as "the default", so choose Blue again in
  Options › Appearance to keep it.

## Fixes

- **The Windows installer installs again.** 0.6.2's MSI stopped before its first screen
  with Windows Installer error 2228, so it never asked who to install for. Every MSI is
  now tried through its first steps for both choices when it is built, and the release
  checks install, upgrade, repair and remove it on a disposable Windows machine.
- **A key pressed while the folder changes is no longer ignored.** Checksums (Ctrl+F8),
  Copy and Move (F5, F6), the clipboard (Ctrl+C, Ctrl+X), Properties, the context menu
  and Custom Commands wait a moment for the selection; a change in the shown folder in
  that moment (a download, build output, an antivirus scan) cancelled them without a
  word. The folder is now read again right after the action instead.
- **Delete or F8 where no Recycle Bin or Trash takes the items asks once, right away.**
  On a drive set to "Don't move files to the Recycle Bin", on a network share, USB stick
  or memory card (Windows), or on another filesystem than your home Trash (Linux), F8
  started a Move to Trash that stopped at 0% and asked in a second window whether to
  delete permanently instead. F8 there now opens the same confirmation as Shift+Delete,
  with one line that says why; Cancel keeps everything. An item the Trash still refuses
  after the Delete started is kept, and the job asks Retry, Skip or Cancel job.
- **A file created right after a folder opens is shown.** On Windows, a file created or
  changed in the moment between opening a folder (or restoring tabs) and the start of
  its change watch could stay missing from the panel until something else changed there;
  on both systems such a change could take up to 15 seconds to appear. The panel now
  checks the folder once its watch is in place.
- **A folder opened with authorization stays open.** After **Retry with authorization**
  the files appeared, and about a second later the panel went back to the folder you
  came from: its change watch checked the folder with your own rights, and the denied
  check started a re-read that recovered to the parent. Such a listing is now kept as
  listed and its status row says it is not updated automatically; Refresh (Ctrl+R) offers
  authorization again while access is still denied.
- **Closing an HTML viewer no longer holds up the exit or an update.** On a busy Windows
  machine, closing an HTML viewer or following a link in it could wait for the browser
  for many seconds. If the application closed meanwhile, it reported that viewer cleanup
  took too long and skipped a requested **Restart now** or **Install now**. The wait for
  a closed browser now ends after two seconds.

## Current limitations

- Archives are read-only, and RAR is not supported.
- On Linux, native Wayland drag and drop with other applications is off unless
  `MIDNIGHT_WAYLAND_DND=1`; X11 and XWayland use XDND. GVfs locations still appear in the
  drives list on its regular refresh rather than at once.
- Compare Directories remembers its options only until the application closes.
- Network Neighborhood asks for credentials on Linux only, and has not been run against a
  real SMB server.
- Each open viewer or comparator window keeps its own worker and, for images, PDF, HTML
  and video, its own helper process: many large documents open at once use memory
  accordingly.
- macOS is not implemented, and the Windows executable and installer are unsigned.
