# Midnight Explorer 0.6.5 — preview

A fix release after the [0.6.4 preview](https://github.com/TomasJelinek/fm/releases/tag/v0.6.4):
Copy refuses a folder's own subfolder again on USB sticks, memory cards and discs, the
authorization helper never opens a file, and large listings and quick search are faster.

## Downloads

- **Windows x64, installer:** `midnight-explorer-0.6.5-x86_64-pc-windows-msvc.msi`.
  It asks who it is for: **Just for me** installs without administrator rights into
  `%LOCALAPPDATA%\Programs\Midnight Explorer (MSI)`; **For all users** asks for
  administrator approval and installs into `C:\Program Files\Midnight Explorer (MSI)`.
  Each adds a Start menu entry and an entry under Settings › Apps › Installed apps to
  repair or remove it; removing it leaves your settings. The installer is unsigned.
- **Windows x64, archive:** `midnight-explorer-0.6.5-x86_64-pc-windows-msvc.zip`. Extract
  the complete archive to a folder and run `midnight-explorer.exe`; keep the `viewers`,
  `filesystems` and `thumbnailers` folders beside it. Targets Windows 10 22H2 and
  Windows 11; the executable is unsigned. Neither Windows download needs the Visual C++
  runtime.
- **Linux x86-64:** `midnight-explorer-0.6.5-x86_64-unknown-linux-gnu.tar.gz`. Extract it
  with tar and run `./midnight-explorer` in an X11 or Wayland desktop. Built on Ubuntu
  24.04 (glibc 2.39 baseline); the archive's README lists the runtime packages.
- **`SHA256SUMS`** and **`SHA256SUMS.minisig`:** the checksums of the three downloads and
  their minisign signature by the release key. 0.5.1 to 0.6.4 offer this version through
  their update check and install it only when the signature and checksums match.

## Upgrading

- **From an MSI installation of 0.6.3 or 0.6.4:** the update dialog's **Install now**
  downloads the 0.6.5 MSI, checks it against the signed `SHA256SUMS` and lets Windows
  Installer replace the installed copy (with Windows' administrator prompt for an
  all-users installation).
- **From a 0.6.1 MSI installation:** run the 0.6.5 MSI once and choose **Just for me**.
- **From an extracted copy:** use the update button beside Options and About, or
  About › Check for updates; or extract the new archive over a copy of the old folder.
- Settings are kept as they are.

## Fixes

- **Copy refuses a folder's own subfolder on USB sticks, memory cards and discs
  (Windows).** 0.6.4 let Copy read from FAT32, exFAT, CD and DVD drives, but there it no
  longer noticed that the destination was inside the source folder: copying `E:\a` into
  `E:\a\b` was not refused. It is refused again, as on every other drive.
- **The authorization helper never opens a file (Windows).** Within a folder opened with
  **Retry with authorization**, a request that named a file inside it made the
  administrator helper open that file before refusing it. The helper now asks Windows for
  a folder only, so a file is refused without being opened, as the security notes always
  said.

- **A Copy or Move no longer hangs when another job's folder changes (Windows).** Two
  jobs could each hold a lock the other needed when a folder they shared was renamed or
  a job slot was retired at the same moment; the job then waited forever, and every job
  waiting for its folders waited too.
- **Every leftover staging folder is reported (Windows).** At a job's end, only the first
  `.midnight-stage-*` folder that could not yet be removed was named; the others could
  stay on disk unmentioned. All of them are now named in the job's message.
- **A Delete of a very large selection keeps its report short.** Targets kept because
  they still contain skipped items are named up to 16 and then counted.

## Faster

- **Listings on Windows format their times faster:** 1.4 to 5.7 times less work per row
  for the date and time columns, depending on how spread out the files' times are.
- **The first quick-search keystroke in a large folder** takes about half as long
  (100,000 rows: 36 ms instead of 71 ms).

## Changed for developers

- The obsolete-code sweep removed unused code and stale lint allowances; the manual
  measurements and probes and their variables are listed in the
  [test execution guide](https://github.com/TomasJelinek/fm/blob/v0.6.5/docs/developer/test-execution.md).
- The build-script tests run side by side on Windows (about 64 s instead of 216 s).

## Current limitations

- Archives are read-only, and RAR is not supported.
- On Linux, native Wayland drag and drop with other applications is off unless
  `MIDNIGHT_WAYLAND_DND=1`; X11 and XWayland use XDND. GVfs locations still appear in the
  drives list on its regular refresh rather than at once.
- Compare Directories remembers its options only until the application closes.
- Network Neighborhood asks for credentials on Linux only, and has not been run against a
  real SMB server.
- Each open viewer or comparator window keeps its own worker and, for images, PDF, HTML
  and video, its own helper process: many large documents open at once use memory
  accordingly.
- On Linux, Copy and Move to FAT, exFAT and NTFS drives and to network mounts are
  refused, and Rename, Delete and Trash on NFS and sshfs mounts too. On Windows a Move
  from a FAT32, exFAT, CD or DVD drive is refused.
- macOS is not implemented, and the Windows executable and installer are unsigned.
