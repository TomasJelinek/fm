# Midnight Explorer 0.6.4 — preview

The release after the [0.6.3 preview](https://github.com/TomasJelinek/fm/releases/tag/v0.6.3):
one authorization opens a folder with its subfolders, the selection keys include folders,
images, documents and archives on USB sticks, memory cards and some network shares open
again, the installer refuses a second kind of installation instead of leaving files
behind, and the documents carry lowercase names.

## Downloads

- **Windows x64, installer:** `midnight-explorer-0.6.4-x86_64-pc-windows-msvc.msi`.
  It asks who it is for: **Just for me** installs without administrator rights into
  `%LOCALAPPDATA%\Programs\Midnight Explorer (MSI)`; **For all users** asks for
  administrator approval and installs into `C:\Program Files\Midnight Explorer (MSI)`.
  Each adds a Start menu entry and an entry under Settings › Apps › Installed apps to
  repair or remove it; removing it leaves your settings. The installer is unsigned.
- **Windows x64, archive:** `midnight-explorer-0.6.4-x86_64-pc-windows-msvc.zip`. Extract
  the complete archive to a folder and run `midnight-explorer.exe`; keep the `viewers`,
  `filesystems` and `thumbnailers` folders beside it. Targets Windows 10 22H2 and
  Windows 11; the executable is unsigned. Both Windows downloads need the Microsoft
  Visual C++ x64 runtime if it is not already installed.
- **Linux x86-64:** `midnight-explorer-0.6.4-x86_64-unknown-linux-gnu.tar.gz`. Extract it
  with tar and run `./midnight-explorer` in an X11 or Wayland desktop. Built on Ubuntu
  24.04 (glibc 2.39 baseline); the archive's README lists the runtime packages.
- **`SHA256SUMS`** and **`SHA256SUMS.minisig`:** the checksums of the three downloads and
  their minisign signature by the release key. 0.5.1 to 0.6.3 offer this version through
  their update check and install it only when the signature and checksums match.

## Upgrading

- **From an MSI installation of 0.6.3:** the update dialog's **Install now** downloads the
  0.6.4 MSI, checks it against the signed `SHA256SUMS` and lets Windows Installer replace
  the installed copy (with Windows' administrator prompt for an all-users installation).
- **From a 0.6.1 MSI installation:** run the 0.6.4 MSI once and choose **Just for me**.
- **From an extracted copy:** use the update button beside Options and About, or
  About › Check for updates; or extract the new archive over a copy of the old folder.
- Settings are kept as they are.

## New and changed

- **One authorization opens a folder and its subfolders.** After **Retry with
  authorization** and one administrator (or polkit) approval, the folder's subfolders open
  without asking again, and Refresh (Ctrl+R) lists them again without a prompt, for up to
  5 minutes without use and 30 minutes in all, in that panel. Going above the folder,
  to another drive, tab or view, or closing the panel or the application ends it. The
  helper lists names and details only: it refuses folders outside the approved one,
  including links and junctions that lead out, and files inside still cannot be opened.
- **Selection keys include folders; Shift means files only.** **Ctrl+A** selects files
  and folders (Ctrl+Shift+A selects files only), **Ctrl+I** inverts files and folders
  (Ctrl+Shift+I files only), and **Ctrl+D** deselects everything while the new
  **Ctrl+Shift+D** deselects files and keeps marked folders (also F10 › Selection ›
  Deselect files only). Num +, Num − and Num * still follow the Select by mask dialog's
  Include folders choice. Keys you changed in Options › Keyboard stay as you set them;
  **Restore all defaults** there brings the new ones.
- **One kind of MSI installation at a time.** The installer no longer installs Just for
  me while Midnight Explorer is installed for all users, or the other way round: that
  choice's Install button is disabled and a note says to remove the other copy in
  Settings › Apps › Installed apps first. A silent installation (`msiexec /qn`) is refused
  the same way. With 0.6.3 both kinds could be installed, and removing one left its files
  behind.
- **Documents with lowercase names.** The documents in the downloads and the repository
  are named in lowercase with hyphens, for example `feature-status.md`,
  `keyboard-shortcuts.md` and `system-requirements.md`.

## Fixes

- **Images, documents and archives on USB sticks, memory cards, CD/DVD and some network
  shares open again (Windows).** Thumbnails, the viewers, comparisons and archives could
  not read any file on a FAT32 or exFAT drive, and on CD/DVD, WebDAV and network shares
  whose server has no 128-bit file IDs, because their file system has no such ID. Such
  a file is now identified by its 64-bit file index, in the application and in the
  native filesystem plugin that reads files for them.
- **Copy from a USB stick, memory card, CD or DVD (Windows).** Copy, checksum
  calculation and drags refused files on FAT32, exFAT, CD and DVD drives ("requires
  stable file identities"). They now read them as they read network shares without file
  IDs. A Move from such a drive is still refused; copy, then delete.
- **Find and folder sizes on shares without file IDs (Windows).** On WebDAV folders and
  SMB servers that report the same file ID (zero) for every file, recursive Find
  refused every subfolder as a cycle, duplicate search found nothing, and folder sizes,
  Properties and the folder tree counted only the first folder. Such folders are now
  told apart by their paths.
- **Rename and Delete on NFS and sshfs say why they are refused (Linux).** These mounts
  cannot rename without replacing another entry, which Rename, Delete and Trash need;
  the message said only "Invalid argument (os error 22)". What each file system supports
  is listed under [File systems](https://github.com/TomasJelinek/fm/blob/v0.6.4/docs/user-guide.md#file-systems).
- **A viewer opens when only a file's metadata changed.** A PDF or image viewer could
  refuse to open ("Source changed since capture") when endpoint protection or a backup
  tool had touched its plugin's manifest without changing it. The manifest is now read
  again and accepted when its content is unchanged.
- **The HTML viewer's watchdog wakes once per burst of writes**, not once for every write
  that raced its wake-up.

## Current limitations

- Archives are read-only, and RAR is not supported.
- On Linux, native Wayland drag and drop with other applications is off unless
  `MIDNIGHT_WAYLAND_DND=1`; X11 and XWayland use XDND. GVfs locations still appear in the
  drives list on its regular refresh rather than at once.
- Compare Directories remembers its options only until the application closes.
- Network Neighborhood asks for credentials on Linux only, and has not been run against a
  real SMB server.
- Each open viewer or comparator window keeps its own worker and, for images, PDF, HTML
  and video, its own helper process: many large documents open at once use memory
  accordingly.
- On Linux, Copy and Move to FAT, exFAT and NTFS drives and to network mounts are
  refused, and Rename, Delete and Trash on NFS and sshfs mounts too. On Windows a Move
  from a FAT32, exFAT, CD or DVD drive is refused.
- macOS is not implemented, and the Windows executable and installer are unsigned.
